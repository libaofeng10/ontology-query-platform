# Claude 问数根因诊断

后续进展：用户已明确要求移除表列白名单、已确认 JOIN 和先读取结构要求。代码已据此分离元数据与查询权限，快照提供完整已采集目录，增加物理表读取并修正对象关键词检索。第一版回放发现物理表读取丢失业务对象和知识背景，导致 Claude 再次选择 Alpha 路径；最终从工具契约补齐表、对象和知识之间的上下文，而不是增加 GPT 专用判断。完整回归 572/572，正式原问题回放为 3 个工具步骤、1 次 SQL、0 失败。以下记录描述改动前的诊断。自由文本结论的业务正确性仍由 Claude 判断，没有恢复平台意图解析或新增语义前置拒答。

2026-09-04。范围：用户反馈“GPT 使用情况走了 Alpha 用户路径，最后错误声称没有记录”，以及要求不要只修单个问法。本轮用本地合成数据经过真实 query-service、bridge、MCP 和 SQL 内核验证；模型输出及数据库响应固定，不调用外部模型，不修改生产配置。

核心问题是输入信息和结果验收没有形成一致的契约。Claude 已直接承担理解问题、选表和生成 SQL，但它能读取的元数据仍由一套混合规则裁剪；最终验收能确认 SQL 执行来源，不能确认业务结论是否得到支持。此前补齐字段和知识后原句回放成功，只证明该场景恢复，不代表通用问题已解决。

1. **语义映射兼任列权限。** `server/src/claude-query-snapshot.mjs` 的 `buildPublicColumns` 只保留属性映射、主键/唯一键、已发布关系引用、已验证知识引用及固定名称的状态/时间列。`query-service.mjs` 随后直接把这个集合作为内核的 `allowedColumns`。因此“未建立属性映射”和“无权查询”没有区分。对照实验中，同一个 `alpha_account_user.phone`，无映射时不可查询，单独添加属性映射后可查询，仅添加知识中的物理字段引用也会变成可查询；没有修改权限配置。补一列恢复一个场景，是这个耦合的表现。
2. **工具输入和读取语义不一致。** 此前 `get_knowledge` 忽略 query、search 将多个词作为连续字符串，已局部修复；但当前 `get_objects` 仍忽略 query。合成目录中传 `query: "AlphaGPT"` 会返回 Alpha 和 AlphaGPT 两个对象。它只识别对象标识或显示名称：对象标识 `product_account` 能读到对象，物理表标识 `alpha_account_user` 读不到。后者没有在接口中说明，因此模型必须额外猜测标识类型。这是可复现的工具设计缺口；原审计 138 并未证明物理表标识读取导致了那次失败。
3. **执行来源验证不等于答案证据验证。** 当前 answered 只要求成功执行的 execution IDs 和自由文本 conclusion。用字段齐全、描述已区分产品的两个对象，只执行一次 Alpha 查询并返回空集，再提交“该客户没有 GPT 使用记录”，平台仍返回正常答案，审计中的 intent 为 null。未触发 SQL 预算错误时，上一轮新增的预算拦截不起作用。在同一合成场景中保留五次预算、增加一次超预算请求后，平台才会拒答。这证明预算耗尽是一个可检测症状，缺失的是结论与目标业务对象、口径及查询结果之间的约束。

当前真实故障的因果链是：概览省略产品描述、GPT 手机号映射遗漏及知识检索缺陷共同降低正确路径的可发现性 → 模型选择名称相似的 Alpha 路径 → 空结果和修正尝试消耗 SQL 预算 → 模型把另一产品的空结果解释为 GPT 无记录 → 平台接受有执行凭据但证据不充分的结论。未确认 JOIN 的拦截本身符合现有关系规则，增加预算也不能纠正产品归属判断。

治本的改造应把三个责任分开：

- 查询授权单独确定允许访问的数据源、表和列；语义映射用于解释业务含义，不能隐式授予或撤销列权限。需要明确既有发布范围和实际授权的关系，不能简单删除 SQL 白名单或开放所有表来掩盖问题。
- 本体工具提供一致的对象/物理表寻址、关键词筛选和分页；选择对象后能获取其字段、枚举、已确认关联及相关定义。没有命中、内容缺失与确实不存在需要明确区分，不能让模型依赖 SQL 报错摸索结构。
- Claude 自行给出目标业务对象、查询口径、结果引用及未完成部分；平台校验引用对象、实际执行表和结果之间的一致性。未执行、失败、截断、辅助定位不能冒充目标查询已完成。业务歧义交给 Claude ASK；不恢复已移除的平台意图预解析和字段覆盖前置拒答。模型自报的对象选择仍可能错误，因此结构校验不能被宣称为自然语言结论的完全正确性证明。

验收也必须从“原句查询成功”和模拟模型的接口契约扩展到真实模型的业务用例：等价问法、不同客户、Alpha 无记录而 GPT 有记录、目标产品确实无记录、多产品部分完成、元数据缺失，以及预算内提前给出错误否定。对每例检查产品、过滤字段、关联、计量单位和结论证据，不能仅检查接口成功或 SQL 可执行。
