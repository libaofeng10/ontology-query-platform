# 数据源关系识别与本体生成修复方案

日期：2026-09-07。依据 [代码评估](SOURCE_ONTOLOGY_RELATION_ASSESSMENT.md)。本轮先记录方案，再实施和验证；不创建 Git commit，不触发生产重建或部署。

## 目标

保留“结构与数据采样 → LLM 识别 → 本体生成”的现有路线，从输入证据、输出契约和关系表示上修复已确认的问题。保持现有选表、只读连接、模型配置和 85 分策略；补充的候选仍需验证，不能凭模型输出直接获得 JOIN 权限。

## 实施顺序

### 1. 严格区分模型否定、证据不足与未完成判断

- 按 candidateId 校验每个模型结果的枚举、置信度和基数；缺失、重复、非法结果不能补成负向结论。
- 对漏答候选进行有界补问，仅重试未完成部分；完整率按有效结果计数。
- 仍未完成的候选保留为待处理，分析状态为 partial/failed，保护已有人工决策。
- 验收：模型返回空 JSON、漏答、重复 ID、非法分数时，没有候选因“没有判断”而被拒绝；有效负结论仍正常生效。

### 2. 建立可解释、具有新鲜度的数据证据

- 将关系数据验证收敛到公共函数；从有限源值出发，按数据库等值比较查询目标表实际匹配，替换“两边前缀样本求交集”。
- 在预算内覆盖源值两端，输出样本数、匹配数、匹配比例、重复匹配、取样方式、时间及失败状态。采样统计不冒充全表事实。
- 保留数值 overlapRatio 兼容现有调用，同时向 LLM 提供结构化证据。
- 本次画像失败或未覆盖时，不向模型提供旧值作为本次有效样本；画像附带采样时间、数量和方式。
- 验收：源 501～1000、目标 1～1000 的包含关系不再误算为零；重复目标、空样本、超时、画像失败均可辨别。

### 3. 扩大有语义依据的候选范围

- 允许有清晰表名或注释语义的无后缀引用、共享主键引用和未建索引目标进入受限验证。
- 删除与当前字段采样策略冲突的旧字段名过滤；仍排除无语义依据的通用 id=id、自等式和明显类型冲突。
- 保留每列目标数、总候选数和查询超时预算；不引入全库字段笛卡尔积的模型调用。
- 验收：customer、业务角色字段、共享主键与无索引业务键有正例；无关通用 ID、范围外表有反例。

### 4. 从结构目录保留联合约束

- 区分单列唯一与联合唯一，保留约束名、列序和完整列组。
- 联合外键以一个关系及其多个列等式表达；保留单列关系的兼容字段和 relationId 引用方式。
- 本体校验、受 Schema 约束的 SQL 编译和 JOIN 校验使用完整等式组，拒绝只满足部分联合条件的 JOIN。
- 历史目录通过重新探查更新；旧的逐列外键不能继续冒充完整联合关系。
- 保持已有 Claude 查询路径的独立只读策略，不把本次修复扩大成查询模式重构。
- 验收：联合唯一成员不再被当成单列唯一；完整联合 JOIN 通过、缺项 JOIN 被受 Schema 约束的执行路径拒绝；单列 JOIN 回归不变。

### 5. 全局补边、确认闭环与关系覆盖

- 同次编排中的对象完成后，以统一端点集合补生成跨域关系，支持自引用角色；保留对象批次的预算和恢复能力。
- 将待确认物理关系及未完成识别纳入构建待处理项，确认后刷新相关依据并继续原构建，避免表全覆盖却悄悄缺边。
- 对已确认物理关系统计本体 Link 覆盖，遗漏应明确可见并触发有界补充，不能仅根据对象缺表情况结束修正。
- 验收：跨批关系、自引用、确认后续跑、遗漏 Link、重试幂等和失败不覆盖生效版本。

### 升级与能力边界（第一阶段记录，后续变化见第二阶段）

1. SQLite 关系表采用事务迁移，保持历史 relationId。旧外键记录没有保存约束分组，迁移不会猜测组合，而是暂时停用这些记录；旧列唯一性只保留可证明的单列主键。重新探查后恢复可证明的单列外键或写入完整联合外键。已有版本内容不被直接重写，需要基于新目录检查并重建关系映射。
2. 本轮支持数据库已经声明的联合物理关系；LLM 逻辑关系候选仍为单列对，尚未增加无外键联合逻辑关系的自动发现。
3. Object 的 primaryKey 仍是单个属性。只有联合主键、没有单列唯一标识的表会被校验拦住，不会选第一成员冒充唯一标识。
4. 自引用可以成为本体 Link，也可通过有明确角色别名的受约束 SQL 查询。结构化 Query Plan 仍按物理表分配别名，尚未扩展同一对象的多角色属性引用语法；仅支持单列关系的角色归属快捷推断不会再使用联合关系的首成员。
5. 完整联合条件校验适用于语义编译和 Schema 约束的 SQL 路径。条件须在同一 ON 或 WHERE 的 AND 组中成立；不支持用 OR、不同别名或不同子查询拼凑。Claude 独立只读路径保持原契约，收到完整关系证据，但未新增本体 JOIN 白名单。
6. 采样比例只描述所取源值的匹配情况，不能当作全表包含率或真实关系准确率。没有连接真实 MySQL 数据源或调用真实模型；SQL 经过解析及调用链测试，仍需在实际数据库版本与业务真值集上验收执行计划、时延和识别效果。

本轮未创建 Git commit，未执行生产迁移、数据源重建或部署。

## 第二阶段方案（2026-09-07，继续实施）

以下补齐上一轮明确列出的能力缺口；上面的验证数字属于第一阶段，不能作为本阶段验收结果。

1. **主动候选与联合逻辑关系**：增加独立的 LLM 提案步骤，将有界的结构、完整键约束和新鲜列画像交给模型。服务端核对选表范围、字段、类型、完整列组并去重，和规则候选合并后才采样、审阅；模型提案不直接成为已确认关系。支持未声明外键的多列关系，规则可依据联合唯一键构建完整候选。记录预算耗尽及提案失败，避免声称全库已覆盖。
2. **分层与补采样**：关系证据支持元组比较，并按目录中实际存在的租户、状态及时间字段选择有界分层。首轮不确定、低置信度或采样失败触发一次补采样与复核；查询数、样本量、超时均受限。保留首轮与复核记录，不把不同样本的比例直接平均成全表事实。
3. **联合对象标识**：保留单列 `primaryKey` 字符串兼容，增加属性名数组表示联合标识。依据完整唯一约束校验所有成员、映射、必填和继承；对象生成、评分、编辑和查询使用同一套标识语义。
4. **查询角色**：Query Plan 增加显式角色与 Link 路径，属性可按角色引用。每个角色有独立物理表实例和别名，沿所选 Link 编译完整等式；旧计划保持兼容。验收员工与经理同表取不同姓名、复合自引用、无关角色及不完整条件被拒绝。
5. **中间表业务关系**：在两个已确认关系通过同一桥表连接两个对象、桥表键能约束端点组合时，提供有界的业务 Link 路径候选，绑定完整有序 relationMappings。明确区分物理边覆盖与业务路径候选，沿桥表查询，避免把中间表数据直接当成端点对象。
6. **效果验收工具**：增加关系真值格式与可重复评测入口，分别报告候选召回、关系精确率/召回率、方向、基数及耗时。先用合成数据验证指标和调用链；真实 MySQL、真实模型及生产重建在获得具体数据源和业务真值后执行，不能用模拟测试宣称真实效果。

各项先补行为测试再改主链路。完成后运行后端回归、构建、渲染及本轮代码 lint，并在本文追加实测结果与外部验收依赖。继续遵守不主动提交 Git commit。

## 类型检查修复（2026-09-07）
