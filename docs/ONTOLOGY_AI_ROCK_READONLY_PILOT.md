## 执行与验收

1. 在设置中心保持 `review`，由 editor 创建上述范围的生成批次。
2. editor 在审核页按需展开“模型调用留痕”和候选“状态与校准历史”，核对 Prompt、原始输出、确定性评分与物理证据。
3. 使用首轮审核身份确认、拒绝或合并候选；再切换到另一个 editor/admin 身份，对模拟自动确认候选补齐“准确 / 错误 / 大幅修改”独立双检标签。同一身份不能同时充当首轮审核人与双检人。
4. 应用确认候选为不可变草稿，运行完整 Schema 校验与 Diff。
5. 为试点域补充正式 Gold SQL 评测集，并针对该草稿运行语义对照门禁；该次门禁可作为发布保护。
6. 人工核对并发布试点 Schema；在校准看板选择 Gold SQL 已补齐的同一评测集，点击“运行发布后门禁”，由后台任务对当前发布版本执行 `off` 对 `prefer` 的语义门禁并形成带 Schema 发布时间快照的发布后证据。看板会持续显示任务步骤和进度。
7. 确认看板中的 Gold/总数与 Held-out 数符合预期，再填写人工补录对象数并保存门禁快照；看板只接受当前评测集校验和、当前发布 Schema、发布时刻快照与真实语义执行均匹配的门禁。评测集缺少 Gold SQL、Schema 未发布或已被新版本替代时，运行或校准入口会保持关闭。
8. 只有全部条件通过后，admin 才能从门禁快照启用 `auto_draft`；普通设置 API 不能绕过门禁。

自动确认精度门禁保持 80 分产品阈值不变，并要求：目录校验和仍然有效、首轮审核与独立双检身份不同、双检样本不少于 40、准确率不低于 95%、物理映射/未确认 JOIN/敏感字段错误均为 0、人工补录对象占比不高于 20%、试点 Schema 已发布且仍是当前版本、发布后 Gold SQL 等价门禁通过且评测集未变化、失败率/延迟/Token 在配置预算内。目录漂移批次、同人标签和过期评测门禁保留审计，但不会计入通过证据。
