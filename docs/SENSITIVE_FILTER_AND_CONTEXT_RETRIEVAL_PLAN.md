# 问数字段检索与会话上下文增强技术方案

> 版本：v1.1  
> 日期：2026-08-17  
> 状态：工程实施完成，待真实数据验证

## 1. 背景

真实会话中，用户明确说明 `13774665233` 是手机号并指定 Alpha 用户位于 `alpha_user`，系统仍生成了：

```sql
SELECT au.expire_time
FROM alpha_user AS au
WHERE au.alpha_id = '13774665233'
```

随后追问“13774665233是手机号呀”，检索范围又漂移到了 `tp_finance`。

根因包括：

1. 问数上下文删除了标记为敏感的字段，模型看不到 `alpha_user.alp_cell`；
2. 表检索只使用当前一句问题，上一轮范围仅在当前检索完全无命中时回退；
3. SQL 护栏没有校验“手机号格式的值是否绑定到手机号字段”；
4. 会话标题只是首问截断，不是参与检索的会话摘要。

## 2. 目标

- 问数链路不再根据 `isSensitive` 隐藏、禁用或区别处理字段；
- 所有字段名称、类型和注释都参与表检索、结构 Prompt 和 Agent `get_schema`；
- 所有字段都可用于 SELECT、WHERE、聚合、分组、排序和 `sample_data`，继续受只读 SQL、字段白名单、JOIN、枚举、LIMIT 与 EXPLAIN 护栏约束；
- 从字段名、注释和脱敏画像格式推断手机号、邮箱、身份证等字段语义；
- 从问题识别手机号等格式值，阻止明显的“手机号值绑定普通 ID”错误；
- 短追问和纠正语句携带最近用户消息及上一轮表范围参与检索。

## 3. 范围边界

本次只取消问数执行链路中的敏感列限制：

- `query-service.mjs`；
- `query-agent-loop.mjs`；
- 语义 Query Plan 编译与评测 Gold SQL 策略。

以下探查和建模能力继续保留：

- 数据源字段的 `isSensitive` 标记；
- 列画像对敏感原值的抑制；
- 本体候选生成时的敏感证据标记。

这些标记不再影响问数表检索和 SQL 字段白名单。

## 4. 字段语义校验

### 4.1 字段类型推断

根据字段名、注释及画像的 `sensitiveKinds` 推断：

- `phone`：`mobile`、`phone`、`cell`、手机号等；
- `email`：`email`、邮箱等；
- `china_id`：`id_card`、身份证等；
- `bank_card`：`bank_card`、银行卡等。

该分类只用于提升字段选择正确率，不产生访问限制。

### 4.2 问题值识别

本地识别问题中的手机号、邮箱、身份证和银行卡格式。当这些值出现在 SQL 等值或 `IN` 条件中时，SQL 护栏检查目标字段语义。

例如：

- `alp_cell = '13774665233'`：允许；
- `alpha_id = '13774665233'`：拒绝并反馈“手机号值绑定到了非手机号字段”，让规划器修正；
- 普通不具备明确格式的业务 ID：不增加额外限制。

## 5. 会话上下文检索

### 5.1 追问识别

对于“是手机号呀”“那它呢”“不对，应该是……”等短追问或纠正语句，检索文本由以下内容组成：

- 最近两条用户消息；
- 当前问题；
- 上一轮和最近使用过的表作为优先结构范围。

完整的新问题仍只按当前问题检索，避免旧话题污染。

### 5.2 会话状态

`context_json` 保存：

- `tableNames`：上一轮实际执行表；
- `recentTableNames`：最近使用表；
- `pageSlugs`：上一轮知识页；
- `recentPageSlugs`：最近知识页。

规划历史中的助手消息增加“查询范围”摘要，但不加入完整 SQL。

## 6. 实施范围

- 新增字段语义模块，统一字段类型和问题值识别；
- 修改结构检索，使所有字段参与评分；
- 修改 Legacy Prompt 与 Agent Schema，展示所有字段及可选 `semanticKind`；
- 修改 SQL 护栏，增加值格式与字段类型匹配校验；
- 修改会话检索和状态更新；
- 修改语义 Query Plan 与评测策略，使其不再因 `isSensitive` 拒绝字段。

不新增外部 API，不修改数据库结构。

## 7. 验收标准

1. 问数 Prompt 和 Agent Schema 能看到 `alpha_user.alp_cell`；
2. `alp_cell` 可以用于 SELECT、WHERE 和采样，与普通字段一致；
3. `13774665233` 绑定 `alpha_id` 时被语义校验拒绝；
4. `13774665233` 绑定 `alp_cell` 时可正常执行；
5. “13774665233是手机号呀”继续携带上一轮 `alpha_user` 范围检索，不再只命中无关手机号表；
6. Legacy、Agent、语义 Query Plan 和评测路径行为一致；
7. Lint、完整测试、渲染测试和生产构建全部通过。

## 8. 风险说明

本版本以问数效果为优先，问数链路不再提供敏感字段级访问控制。进入生产多租户或开放用户环境前，应另行设计基于角色、用途和审计的字段权限策略，不能依赖当前 `isSensitive` 标记作为访问控制。

## 9. 实施记录

- 单发 SQL、Agent Loop、语义 Query Plan 和 Gold SQL 评测均改为全字段白名单，不再根据 `isSensitive` 生成 filter-only、禁止输出、禁止聚合或禁止采样规则；
- 删除敏感过滤条件的 SQL 参数化分支，查询与证据统一保留实际执行 SQL；
- 新增 `query-column-semantics.mjs`，只负责字段语义和问题值格式识别，不参与字段授权；
- 短追问会组合最近两条用户消息，并优先保留上一轮及近期表范围；规划历史增加实际查询范围摘要；
- Alpha 回归用例覆盖：先拒绝 `alpha_id = '13774665233'`，随后允许并执行 `alp_cell = '13774665233'`；
- 自动化验证：Lint 通过，服务端 186 项测试全部通过；仍需在真实 Alpha 数据源上做一次问题回放验收。
