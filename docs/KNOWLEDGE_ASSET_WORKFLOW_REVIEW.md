# 知识资产页面职责与操作流程评估

评估日期：2026-09-05。依据当前代码及 `39.107.117.246` 数据源 2 的只读统计。本次没有修改线上服务、知识、确认状态或查询配置。

结论：保留补充业务知识的能力，将“知识资产”收敛为“业务知识”。表结构、字段与关系由“数据源与本体”统一维护；运行故障留在审计；问答中的临时澄清留在当前会话。当前不流畅的根源是这些职责混在一起，且部分状态仍沿用旧问数流程。

## 根源与实际消费路径

1. **重复展示与重复维护入口。** `server/src/knowledge-service.mjs` 的 `list()` 将物理表、关系与规则包装成知识页面，再混合人工知识。26 张自动表页面的 `verified` 固定为 false，前端查看按钮却不可操作，因此“总数／已验证数”不是有意义的待办完成度。

2. **关系存在两套可编辑状态。** 在知识页编辑自动 JOIN 时，`save()` 写入 `ds_knowledge_page`，不更新 `ds_relation` 或对应的 `ds_question`。消歧确认则更新关系记录。按同一 slug，人工知识还会遮住自动关系页面的显示状态。这是代码上的分叉风险；当前线上没有人工 JOIN 知识记录，尚未查到此类已发生冲突，不能把它当成本次线上故障事实。

3. **失败聚合缺少适合当前流程的生命周期。** `server/src/capability-gap-service.mjs` 从最近最多 500 条审计中取失败/拒答，继续使用旧意图解析的概念匹配判定少数指标、筛选缺口。没有结合当前 Claude 模式、后续回放结果或人工归档。`CLASS:*` 类问题始终返回 open，只要还在统计窗口里就会持续展示。因此“补齐资产后自动闭环”的页面文案不适用于大多数条目。

4. **表单要求与业务补充不匹配。** `KnowledgeEditor` 和后端 `validatePage()` 对术语、规则也强制要求 SQL；标记验证时还要手填负责人。列表没有按来源或业务用途分组、分页，补充一段业务说明要进入技术表单，并理解多个独立状态。

5. **业务知识仍有实际用途。** `server/src/claude-query-snapshot.mjs` 从存储读取人工知识和规则，将已验证且适用的内容提供给 Claude；它通过另一条目录路径读取物理结构、枚举与关系，不依赖将它们再显示为 137 个知识页面。AI 本体生成也读取已验证知识。因此应保留业务补充及其消费链路，统一来源和维护入口。当前 Claude SQL 执行已经不以已确认 JOIN 为准入条件，但关系仍可作为建模与查询参考。

## 建议的页面归属与操作

| 内容 | 归属 | 操作方式 |
| --- | --- | --- |
| 表、字段、枚举、对象与关系 | 数据源与本体 | 同一记录维护；自动结果可查看，仅实际冲突或不确定项集中校正。枚举按字段合并处理，避免逐值弹出重复确认 |
| 业务术语、产品口径、指标定义、例外规则 | 业务知识 | 支持直接填写中文说明；SQL 作为可选示例。展示适用范围与来源，允许草稿；用户明确保存为生效知识后统一供 Claude 和建模读取 |
| 问答中的 ASK | 当前问答会话 | 直接回答继续查询；只有需要复用的业务定义才单独保存为知识，不能将一次查询选择自动推广为全局规则 |
| 模型故障、执行错误、旧规则拦截、预算失败 | 审计与问题排查 | 展示失败及后续回放证据；按故障状态跟踪和归档，不要求补写术语来消除提示 |
| 真正缺少的业务定义或现有定义冲突 | 业务知识中的少量待补充项 | 按业务概念去重，展示受影响问题；一次补充关联多条问题。仅运行成功不足以证明口径已解决 |

普通维护流程应缩短为：打开业务知识 → 新增或编辑说明 → 明确适用范围并保存生效。保存已自动写入 Markdown，“从 Markdown 同步”属于手工文件导入场景，可移入高级操作；不应成为每次维护的必经步骤。

后续重构要同时调整后端资产来源、确认状态、缺口生命周期和前端入口。仅减少弹窗、隐藏菜单或批量标记已验证，无法解决上述根源。迁移时保留已有 5 条人工知识及全部历史记录，不自动确认尚未核实的定义，不重新引入 Claude 意图预检、字段覆盖或 JOIN 白名单。

## 首版调整实现（用户确认后）

- 主导航改为“业务知识”，列表由后端返回人工术语、指标和规则；数据表和 JOIN 继续在数据源与本体、图谱中读取原记录。来源于目录的规则只读展示，保存及 Markdown 导入均阻止覆盖同一目录关系或规则，避免分叉。
- 知识采用列表与正文并排的页面内编辑。提供搜索、类型筛选、草稿筛选及分页。支持仅填写中文说明，参考 SQL 可选；“保存生效”与“保存草稿”是明确的两种操作，维护人由认证身份记录。保留已有 SQL、别名、适用表及结构化口径声明。
- 业务知识只展示当前业务定义的待补充项。审计页集中展示运行问题、旧流程历史和后续执行证据；只有同一问法、同一执行方式的后续成功，才标记为后续执行成功。该状态不等于批准业务知识，也不会盖住后来再次发生的失败。
- 主导航不再单列消歧队列；关系文档、关系与枚举确认合入数据源页面。待确认项按字段分组，用户显式选择后一次保存本组选择，不默认选择建议、不自动确认。
- 图谱移除固定类型区域布局，改为依据可见关系的连通分组与层次布局，动态计算画布范围。提供业务视图、数据映射、完整图谱；搜索保留直接关联，节点详情显示属性与实际关系，可聚焦相邻对象。调整为浅色网格、清晰节点、关系箭头、选中高亮和右侧详情，支持适应画布、拖动、以指针为中心缩放及小屏布局。

验证：本地完整后端回归 589/589，页面生产构建成功，SSR 回归 1/1；修改文件 lint 通过。新增契约覆盖纯文本知识保存／导入／Claude 读取、草稿隔离、认证维护人、目录单一来源、失败生命周期，以及 85 节点含环图的无重叠、可适配布局和搜索／缩放行为。全仓 TypeScript 检查仍有原有的问答事件、评测、示例依赖等类型错误，本次新增组件没有新增类型错误。
