# OntoQuery 实施计划

> 基线：V0.2.1 方案；开始日期：2026-08-12；交付形态：独立本地 Web 项目。

## 实施原则

1. **真实性优先**：除明确标记的演示数据源外，界面不得用静态数字或兜底答案冒充真实状态。
2. **安全先于可用**：真实查询必须依次通过物理只读、AST、白名单、JOIN、枚举、EXPLAIN 和超时护栏。
3. **人的知识只录一次**：人工分级、已验证页面、枚举含义和 JOIN 确认在重建后保留。
4. **每阶段可验收**：代码、API、界面、测试和文档同时完成；未通过出口条件不进入下一阶段。
5. **不自动提交 Git**：所有变更留给维护者审核与提交。

## 阶段与出口条件

### P0｜基线审计与计划（已完成）

- 标记静态 UI、演示 API、真实适配器和缺失链路。
- 建立本计划、实施状态和验收矩阵。
- 出口：可以逐项回答“当前数据来自哪里、是否经过真实执行”。

### P1｜产品非 Demo 化

- 数据源新增、连接测试、数据源切换和只读状态展示。
- 探查结果、消歧问题、知识资产、审计全部由当前数据源 API 驱动。
- 表分级人工覆盖可写回 SQLite，重跑后不丢。
- 查询失败或 API 不可用时明确显示错误，不再回退伪造答案。
- 出口：新建真实数据源后，可从 UI 完成连接测试、探查、分级复核和审计查看。

### P2｜本体资产与检索

- term / metric / join / rule / table 五类资产统一 CRUD。
- Markdown 与 SQLite 双向同步，`verified` 自动覆盖保护。
- 术语/指标优先检索，关键词召回与 Wikilink 一跳扩展，反向确定 5–15 张表。
- Prompt 只携带命中资产、关联表 DDL、规则、SQL 片段和反例。
- 出口：问题的命中页面与入选表可解释，C 级表不进入检索。

### P3｜真实问数编排

- LLM 规划结构化输出、SQL 自修复不超过两次。
- EXPLAIN 成本、执行超时、结果行数、危险函数和敏感列校验。
- 多轮会话保存命中术语、表、过滤条件和时间范围。
- 明确拒答：覆盖域外、缺 JOIN、连续失败、LLM 未配置。
- 出口：真实库端到端返回结论、表格、图表、依据；全部失败有审计记录。

### P4｜异步构建与增量更新（已完成本地单实例基线）

- 持久化探查/评测任务、进度、同源同类任务去重和服务重启安全重排队。
- 待决语义问题独立持久化，不阻塞结构探查；回答记录 `outruled_by` 并写回关系/规则。
- Schema snapshot/diff；删除结构标记为 `present=0`，不物理删除历史元数据。
- 出口：关闭页面不丢任务；重启从安全边界重跑；verified 页面不被自动覆盖。

### P5｜评测与知识闭环（已完成执行器）

- 评测集、held-out、gold SQL、运行记录 CRUD。
- 结果集等价比较（行序无关、数值容差），按检索/生成/执行/结果差异分类。
- 问数依据面板可直接创建或修正知识页并重跑关联用例。
- 出口：任意评测集一键后台回归；30/100+ 题正式集合等待业务方提供。

### P6｜生产加固与验收（已完成部署基础）

- 多身份 token、角色、数据源访问控制、身份/IP/请求类型限流。
- 凭据轮换、CORS 收敛、日志脱敏、备份恢复与运行监控。
- Docker Compose 部署、只读容器基线、健康检查、备份恢复步骤和验收清单。
- 出口：代码侧自动验收已完成；真实库性能、业务准确率、SSO 与备份恢复演练由部署环境留证。

## 外部输入与不阻塞策略

- 没有真实 MySQL：使用独立标记的演示数据源开发，但真实数据源路径必须有自动测试。
- 没有 LLM 凭据：完成 provider、结构化协议和假服务契约测试；真实源明确拒答。
- 没有业务 gold SQL：先完成评测执行器和样例集导入，正式准确率不填虚假数字。
- 没有多用户决策：先实现身份与角色模型，默认本地管理员，不假设企业组织结构。
