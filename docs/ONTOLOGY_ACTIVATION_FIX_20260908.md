# 草稿启用入口与验证反馈修复

## 问题与定位

版本记录此前只展示草稿和“查看执行记录”，没有启用入口。系统验证问题的重试按钮只重新排队；当验证用例没有变化时，任务再次停在同一问题，页面没有反馈检查结论。

rock_readonly 的 v13 包含 26 个对象、210 条关系，相对当前 v11 移除了 5 个仍存在于物理目录的字段：alpha_account.head_img_url、alpha_office.user_create、alpha_office.user_modify、contract.is_valid、feed_action.is_valid。现有关系回归不能证明这些字段移除对查询的影响，继续保留发布验证要求。

## 修复行为

- 本体结果与版本记录都提供启用条件：可直接启用、需要运行验证、缺少用例、结构问题、已有新草稿或其他未处理任务。
- 重新检查为只读操作，展示检查中、检查完成及失败原因，不重复排队也不生成新草稿。
- 验证缺口可跳转到评测页面，携带所选草稿版本；门禁运行明确使用该版本，保存用例后可返回启用检查。
- 当全部不兼容变化都只是遗漏旧属性，并且恢复它们后通过结构检查且没有其他不兼容变化时，提供“保留字段并启用更新”。用户点击后创建新草稿，保留原草稿和新关系，经既有发布检查启用。
- 原草稿直接启用仍需要覆盖全部变化的有效评测。没有伪造 SQL 标准答案，也没有自动更改用户对于字段去留的选择。
- 保存新草稿与任务入队使用同一事务；预先排队任务可正常调度。请求绑定草稿、发布基线、目录、验证用例和工作流快照；重复提交复用本次操作，失败后重新检查可以真正重跑。

## 接口

- `GET /api/sources/:id/ontology-build/activation?versionId=...`：读取条件，数据源查看权限。
- `POST /api/sources/:id/ontology-build/activate`：编辑权限，提交 `versionId`、`mode`（`activate` / `retain_removed_properties`）、读取条件时返回的 `snapshotChecksum`。
- 执行沿用持久化的本体构建任务及原发布门禁。已有人工候选决定、物理关系和旧草稿保持可追溯。
