# 本体候选证据核验修复方案

## 原因与目标

当前低于 85 分的有效候选直接进入人工队列。评分包含表等级、Embedding 相似度、知识和模板数量，缺少模板并不代表存在业务歧义。现有 critic 仅发现明显矛盾，不能提供正向核验结论。本次增加独立的证据核验环节：自动模式中先核验、再修正，只向用户呈现有明确疑点的业务问题。显式人工审核模式保留其原有约定。

## 实施范围

1. 用服务端提供的表字段说明、已确认关系及基数、已接受对象、已验证业务知识和当前版本构造证据集合。模型必须返回明确结论及有效证据引用；“没有明显矛盾”、自报置信度、未知引用、漏项或重复结果不能作为自动通过依据。
2. 结构错误、时间依据缺失、关系类型与基数冲突等先进入有界自动修正。模型不可覆盖结构硬约束。核验失败和生成失败属于系统任务，不要求用户补写业务说明。
3. 正向核验可使低分候选自动通过，保留原评分、核验理由、证据引用和审计事件。结论绑定候选内容、目录、基础版本、接受的端点及知识版本；异步返回后重新检查，保护既有人工决定。
4. 在对象/关系人工问题形成前执行核验；恢复历史任务时同样适用。读取状态只投影现有状态，不调用模型。重复恢复复用有效结论，失败重试与自动修正均有持久化上限。
5. 页面分别呈现系统核验任务与真正的业务问题。自动核验通过的兼容定义变更合并时复用结论，避免再次逐条要求确认；发布影响检查与回归门禁继续执行。

## 验收

- 低分但证据充分的对象和关系自动进入后续构建，评分不人为抬高。
- 模型缺项、伪造引用、返回矛盾或服务失败不能自动通过，也不能变成通用业务说明问题。
- 真正的业务疑点显示具体问题、依据与已有定义；人工决定、目录变更及并发变更受到保护。
- 历史候选可继续核验，无重复确认、无限重试或重复审计。
- 对修正、持久化、恢复和页面分流进行回归，完成类型检查、Lint、构建与现有测试；在既有授权服务器部署并核验状态。
